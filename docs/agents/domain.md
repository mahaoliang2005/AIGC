# Domain docs

This project uses a single context. Keep the glossary at `GLOSSARY.md`
and architecture decision records in `docs/adr/`.

Before exploring, read the glossary and relevant ADRs when they exist.
Use the glossary's terms in specs, tickets, and code. Raise terminology
gaps with the domain-modeling skill. If a proposal conflicts with an ADR,
identify the decision and explain why it should be revisited.

Create glossary entries and ADRs as terms and decisions are agreed.
